# Attendance Lab 0.2.0

Локальное приложение для Linux и Python **3.14.7+**. Дисциплины и датированные занятия, учёт предъявлений PC/SC-карт, позднее сопоставление со студентами, таблица посещаемости и CSV. Приватное рабочее место с журналом, реляционные учебные составы, регистрация по парам и отдельное публичное подтверждение.

Интернет нужен для первоначальной установки зависимостей. После установки приложение работает локально; сервер, аккаунт и облачное хранилище не используются.

## Быстрый запуск без считывателя

Распакуйте архив и перейдите в каталог `attendance-lab`. Нужен **uv 0.12.10 или новее**. Если uv ещё не установлен, используйте [официальную инструкцию](https://docs.astral.sh/uv/getting-started/installation/); установленную старую версию обновите тем же способом, которым она была установлена.

```bash
uv python install 3.14.7
uv run --locked --no-dev attendance-lab --demo
```

Режим `--demo` использует отдельную базу. Раздел **«Настройки»** содержит имитатор; выберите его в списке и нажмите **«Подключить / восстановить связь»**. В поле UID можно вводить тестовые значения, например `00 11 22 33` и `04 AB CD 12 34 56 78`. Поле видно только преподавателю.

## Запуск с ACS / PC/SC

Ваш работающий `pcsc_scan` уже подтверждает настройку ридера. Перед запуском достаточно дополнительно установить зависимости сборки Python-адаптера и, при необходимости, недостающие графические библиотеки.

Ubuntu / Debian:

```bash
sudo apt install build-essential pkg-config libpcsclite-dev swig \
  libegl1 libopengl0 libxcb-cursor0 libxkbcommon-x11-0
```

Arch Linux:

```bash
sudo pacman -S --needed base-devel pcsclite swig libglvnd \
  libxkbcommon-x11 xcb-util-cursor
```

`pyscard` 2.3.1 на Linux собирается из исходников. Заголовки PC/SC требуются даже тогда, когда `pcsc_scan` уже работает. Python, установленный через uv, содержит собственные заголовки; установка системного `python3-dev` другой версии не заменяет их.

```bash
uv run --locked --no-dev --extra pcsc attendance-lab
```

Для нового компьютера также нужны PC/SC daemon и драйвер устройства (`pcscd`, `pcsc-tools`, `libccid` в Ubuntu/Debian; `pcsclite`, `pcsc-tools`, `ccid` в Arch). Существующую рабочую настройку ридера изменять не требуется.

В разделе **«Настройки»** обновите список, выберите нужное полное имя интерфейса и подключитесь. По вашему диагностическому выводу карты появлялись на `ACS ACR1281 1S Dual Reader 00 01`; программа не фиксирует это имя и не выбирает первый интерфейс автоматически.

При запуске без extra `pcsc` главное окно остаётся доступным, но для чтения оборудования потребуется установить extra указанной командой. Имитатор в реальном режиме отсутствует.

## Подготовка и первое занятие

Главное приватное окно содержит четыре раздела: **«Занятие»**, **«Подготовка»**, **«История»** и **«Настройки»**. Публичное подтверждение открывается отдельно. Мышь и клавиатура доступны одновременно.

1. В «Подготовке» импортируйте список за явно выбранный учебный год. Образец — [examples/demo.csv](examples/demo.csv), все записи в нём вымышлены.
2. Создайте дисциплину и зачислите в неё академические группы.
3. Создайте семестровый состав: лекция — несколько групп одного курса; семинар — целая группа; лабораторная — выбранные студенты одной группы. Подгруппы относятся к конкретной дисциплине и семестру. Их можно скопировать в следующий семестр и изменить отдельно.
4. Создайте блок в расписании: дата, состав и начальная пара. В разделе «Занятие» выберите сегодняшний блок и нажмите **F9**. Явно выберите пары, которые подтверждает текущая регистрация.
5. Считывайте карты; для неизвестной карты найдите студента и явно подтвердите сопоставление. Поиск допускает опечатки, перестановку слов и замену `ё` на `е`. Новые неизвестные карты ждут в очереди, текущая карта остаётся закреплённой.
6. **F2** открывает быстрый поиск для ручной отметки, если пропуск не работает. Эта отметка следует охвату активного сеанса.
7. **Shift+F9** закрывает регистрацию. Кнопки открытия и закрытия расположены рядом; текущий охват виден в общей полосе окна.

Просмотр другого блока или отчёта не переключает регистрацию. Принятые события сохраняют ID сеанса, действовавшего в момент чтения. При переключении и закрытии очередь сначала сохраняется в исходный сеанс.

Все занятия используют фиксированные пары:

| Пара | Время |
| --- | --- |
| 1 | 09:00–10:20 |
| 2 | 10:30–11:50 |
| 3 | 12:00–13:20 |
| 4 | 13:50–15:10 |
| 5 | 15:20–16:40 |
| 6 | 17:00–18:20 |
| 7 | 18:30–19:50 |
| 8 | 20:00–21:20 |

Лабораторная Java занимает две последовательные пары, каждая со своей отметкой. Команда расширения регистрации на весь блок распространяет **все предыдущие и будущие проверки этого сеанса на обе пары**, даже если карта была проверена только во время второй пары. Повторно прикладывать карту не требуется. Исходное время проверки сохраняется; фиктивные предъявления не создаются. Занятие можно создать и непосредственно перед началом через форму блока в «Подготовке».

## CSV, справочники и сопоставление

Новый импорт принимает семь колонок строго по [demo.csv](examples/demo.csv):

```csv
Внутренний № по списку;ФИО;Специальность;Профилизация;Курс;Группа;Номер зачётки
```

Сохраняйте **UTF-8 с BOM**, разделитель `;`, одну строку заголовков. Не включайте объединённые ячейки, название ведомости и пустую восьмую колонку. ФИО, специальность и профилизация — целые текстовые ячейки с пробелами. Курс и группа — положительные целые числа. Номер зачётки содержит цифры и хранится **как текст**, сохраняя ведущие нули; это внешний уникальный ключ повторного импорта. Внутренний № по списку служит происхождением строки и не определяет личность студента.

Учебный год выбирается явно. Специальности, профилизации, курсы и годовые группы хранятся связанными сущностями. Профилизация принадлежит специальности, состав группы относится к учебному году. Импорт переиспользует каталоги и обновляет студентов по номеру зачётки; одинаковые ФИО не объединяются. Переименования и псевдонимы каталогов задаются явно. Нечёткий поиск помогает выбирать человека, но не объединяет справочники.

До применения показываются изменения и ошибки. Импорт атомарный, устаревший предварительный просмотр отклоняется. Отсутствие студента в новой выгрузке не удаляет его историю. Старые записи без номера зачётки остаются доступными; их идентичность уточняется вручную.

Реальные выгрузки храните локально в `imports/`. Никогда не заменяйте ими публичный `examples/demo.csv`. Старый трёхколоночный формат [students.csv](examples/students.csv) оставлен для совместимости с предыдущей версией.

Одному студенту можно сопоставить несколько карт. Уже привязанную карту нельзя незаметно назначить другому: исправление ошибочной привязки — отдельная подтверждаемая операция с аудитом всей истории карты. Периоды физической передачи пропуска разным владельцам не моделируются.

## Ручные отметки и история

В текущем блоке выделите строки студентов через **Shift** и зачтите обе пары. В истории выделите прямоугольник **«студенты × пары»** и подтвердите точный список получателей. Историческая операция относится только к выбранным ячейкам и не расширяется на соседнюю пару блока.

Ручные отметки сохраняются отдельными пачками с причиной и временем подтверждения. Это время не означает время прихода. Отмена пачки удаляет только её основание: карточная проверка и другие независимые основания сохраняются. Исторический академический контекст фиксируется отдельно от меняющихся справочников.

Таблицы поддерживают сортировку и клавиатурное выделение. Смена фильтра, дисциплины или периода очищает выделение, чтобы случайно не применить действие к скрытым строкам. Экспорт посещаемости не содержит UID; приватный журнал выгружается отдельно и содержит карты, в том числе неизвестные. CSV защищает текст, похожий на формулу, апострофом.

| Клавиши | Действие |
| --- | --- |
| F1 | Список команд |
| F2 | Ручная отметка активного сеанса |
| F3 | Поиск на текущем экране |
| F6 / Shift+F6 | Следующая / предыдущая область |
| F9 / Shift+F9 | Открыть / закрыть регистрацию |
| Ctrl+Enter | Контекстное подтверждение |
| Esc | Отмена текущего действия или диалога |
| Tab / Shift+Tab | Следующий / предыдущий элемент управления |
| Shift+стрелки | Диапазон строк или ячеек |

Приватные быстрые команды не действуют при фокусе публичного окна и поверх модального диалога.

## Публичное окно

Первая успешная отметка на занятии выделяется **зелёным**, повторная — **жёлтым**. Повтор другой карты того же уже распознанного студента тоже выделяется жёлтым. На другом занятии первое предъявление вновь считается первой отметкой.

Приватные окна и диалоги всегда используют светлую тему независимо от темы рабочего стола. В приватном журнале цветная плашка и подсветка строки показывают последнее полученное подтверждение для просматриваемого занятия. Выделение строки мышью не скрывает цвет; повторное предъявление обновляет существующую строку. Подсветка — текущая обратная связь, при перезапуске она сбрасывается; сохранённые времена предъявлений остаются в журнале.

Результат и ФИО исчезают через **3 секунды**; таймер можно изменить приватно от 1 до 60 секунд. Новая карта сразу заменяет предыдущий результат. При закрытии регистрации ФИО скрывается.

В разделе **«Настройки»** можно выбрать монитор, переместить публичное окно и включить полный экран. Esc возвращает оконный режим. Публичное окно не содержит UID, ATR, технических исключений и элементов управления студентами. Демонстрируйте аудитории только это окно.

## Данные и резервная копия

**Обновление с 0.1.x меняет схему SQLite с 1 на 2.** Завершите старое приложение и запускайте новую версию из отдельного каталога. Перед миграцией автоматически создаётся согласованная копия `*.before-migration.<UTC>.sqlite3` рядом с базой. Все старые ID, карты, предъявления и занятия сохраняются. Старые занятия не получают выдуманный курс или учебный год.

Для миграции без открытия окон:

```bash
uv run --locked --no-dev attendance-lab --migrate-only \
  --db /полный/путь/attendance.sqlite3
```

Команда требует существующую базу правильного режима и блокировку приложения. **Версия 0.1.x не открывает схему 2**: после миграции используйте 0.2.0. Для возврата к старому приложению нужна сохранённая копия схемы 1. Восстановление старой копии в новой версии мигрирует частную временную копию, сохраняя исходный файл резервной копии.

По умолчанию:

- реальная база: `~/.local/share/attendance-lab/attendance.sqlite3`;
- тестовая база: `~/.local/share/attendance-lab/demo.sqlite3`.

При заданном `XDG_DATA_HOME` используется этот каталог. Точный путь виден в приватных настройках. Альтернативный путь и пояс новых занятий можно задать при запуске:

```bash
uv run --locked --no-dev --extra pcsc attendance-lab \
  --db /полный/путь/attendance.sqlite3 --timezone Europe/Minsk
```

У реальной и тестовой баз сохраняется маркер режима; открыть реальную базу через `--demo` или восстановить копию другого режима нельзя. Для одной базы допускается один экземпляр приложения.

Создавайте резервную копию через GUI: SQLite backup даёт согласованный снимок, в том числе при открытом занятии. Для восстановления сначала завершите регистрацию. Перед восстановлением автоматически создаётся страховочная копия `*.before-restore.*.sqlite3` рядом с текущей базой. Не заменяйте работающую SQLite-базу обычным копированием одного файла: рядом могут находиться её WAL/SHM-файлы.

После аварийного прерывания приложение при следующем старте завершает оставшуюся открытую регистрацию и сообщает об этом приватно. Все уже сохранённые отметки остаются; занятие можно явно открыть заново.

Рядом с базой расположен приватный технический `.log` с ротацией. Его содержимое не показывается в публичном окне и не добавляется строками в журнал карт.

Базы данных, включая демонстрационные и резервные копии, WAL/SHM-файлы, дампы, журналы, реальные списки студентов и экспорты не предназначены для GitHub. `.gitignore` исключает эти локальные данные; исключения для CSV — вымышленные `examples/students.csv` и `examples/demo.csv`. Перед коммитом проверяйте состав добавленных файлов; не обходите эти исключения через `git add -f`.

## Разработка и проверка

```bash
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pyright
QT_QPA_PLATFORM=offscreen uv run --locked pytest -q
uv build
```

Группа `dev` содержит только инструменты разработки. Для одновременной разработки с реальным считывателем добавляйте `--extra pcsc` в команды uv, которым нужны аппаратные зависимости.

Контрольный CI описан в `.github/workflows/check.yml`. Результаты проверки конкретного архива и аппаратные ограничения приведены в [VALIDATION.md](docs/VALIDATION.md). Архитектура — в [ARCHITECTURE.md](docs/ARCHITECTURE.md), исходное согласованное описание — в [requirements.md](docs/requirements.md).

Собственные исходники лицензированы MIT. PySide6/Qt и pyscard имеют собственные открытые лицензии; их бинарные зависимости устанавливаются отдельно через uv и не включены в архив проекта.
