# Attendance Lab 0.3.0

Локальное настольное приложение для Python **3.14.7+**, PySide6 и SQLite.
Выбранный семестровый курс объединяет программу, группы, расписание, посещения
и, при необходимости, доклады и письменные работы. Java может использовать только
посещаемость. Интернет нужен для установки зависимостей; рабочие данные остаются
на компьютере преподавателя.

## Запуск

Нужен **uv 0.12.10+**. Установка uv описана в [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).

```bash
uv python install 3.14.7
uv sync --locked
uv run --locked attendance-lab --demo --db /tmp/attendance-example/demo.sqlite3
```

`--demo` включает имитатор и проверяет маркер тестовой БД. В настройках выберите
имитатор и подключитесь. Тестовые UID, например `00 11 22 33`, вводятся только в
приватном окне. Имитатор требует убрать карту перед следующим предъявлением.

Для настоящего PC/SC на Ubuntu/Debian:

```bash
sudo apt install build-essential pkg-config libpcsclite-dev swig \
  libegl1 libopengl0 libxcb-cursor0 libxkbcommon-x11-0
uv run --locked --no-dev --extra pcsc attendance-lab --timezone Europe/Minsk
```

На Arch Linux нужны `base-devel pcsclite swig libglvnd libxkbcommon-x11 xcb-util-cursor`.
Для нового компьютера также установите PC/SC daemon и драйвер устройства:
`pcscd pcsc-tools libccid` на Ubuntu/Debian, `pcsclite pcsc-tools ccid` на Arch.
Рабочую настройку оборудования менять не требуется. `pyscard` на Linux собирается
из исходников и требует заголовков PC/SC.

В настройках обновите список и явно выберите полное имя нужного интерфейса.
Программа восстанавливает соединение с выбранным интерфейсом и подавляет
повторное чтение удерживаемой карты. Физический ридер не проверяется тестами
имитатора и требует отдельной аппаратной проверки.

## Семестровый курс и занятие

Основные разделы: **Занятие**, **Посещаемость**, **Оценки**, **Курс**.
Панели содержат короткие подписи и простые иконки; действия над строкой доступны
после выбора. Настройки и события считывателя находятся в меню «Сервис», архив
старого формата — в его дополнительном подменю.

1. Импортируйте общий учебный список за выбранный учебный год. Используйте
   [вымышленный образец](examples/demo.csv). Состав определяется настройками курса.
2. Создайте курс: семестр, курс обучения, формат и длительность — одна или две
   последовательные пары. Лекции и лабораторные Java — отдельные курсы. Для нового
   семестра создайте самостоятельный курс или копию настроек и состава.
3. Для лекций состав автоматически включает всех студентов выбранного курса
   обучения и учебного года. Для лабораторных и семинаров назначьте академические
   группы или отдельных студентов. Существующую линию можно связать с группами
   через «Изменить состав…», сохранив её занятия и историю.
4. Добавьте общую программу: номер однозначно определяет тему для всех групп.
   Запланируйте разовое занятие или серию через 7/14 дней от первой даты.
   Изменение периодичности действует с выбранной даты; перенос меняет один экземпляр.
   Формат и число пар берутся из настроек курса; выбирается только начальная пара.
5. Выберите занятие и откройте регистрацию (**F9**). Одно предъявление подтверждает
   всё занятие, включая обе пары. Посещение той же темы с другой подгруппой того же
   курса засчитывается с сохранением фактического события.
6. Неизвестная карта остаётся в очереди. Найдите ФИО (**F3**), выберите студента и
   явно привяжите карту. Сохранённая история раскрывается без нового сканирования.
   Новые карты не меняют закреплённую цель, введённый запрос и курсор.
7. **Shift+F9** завершает регистрацию. Просмотр другого занятия и ручные правки
   не переключают действующую регистрацию: её контекст всегда виден сверху.

Фиксированные начала/окончания пар: 09:00–10:20, 10:30–11:50, 12:00–13:20,
13:50–15:10, 15:20–16:40, 17:00–18:20, 18:30–19:50, 20:00–21:20.
Для двухпарного курса выбирается начальная пара 1–7.

Программа не ограничена восемью темами. В «Курс → Программа» двойной щелчок
изменяет название общей темы; «Добавить темы…» добавляет несколько номеров сразу.
При планировании можно выбрать «Новая тема…» и сразу указать номер и название.
Чтобы изменить тему одного экземпляра, выберите его в расписании и нажмите
«Тема занятия…». Это сохраняет даты, отметки и привязку доклада к занятию;
зачёт посещения будет относиться к выбранной теме.

Ручные отметки относятся к явно выбранным студентам и занятию. Shift выделяет
строки/прямоугольник; сортировка сохраняет стабильные ID целей. Причина и время
подтверждения сохраняются отдельно от времени прихода. Отмена пачки не удаляет
карточные и другие независимые основания. Архив прежнего формата доступен через
«Сервис → Данные прежнего формата» для нераспределённых занятий и служебных правок.
В разделе «Посещаемость» выделите ячейку и нажмите **Enter**, **Пробел** или
дважды щёлкните её. Единственное занятие темы отмечается сразу. При нескольких
занятиях выберите конкретную дату и состав. Можно выделить прямоугольник ячеек;
простое выделение ничего не записывает. Повторная команда не снимает и не дублирует
посещение. Переключаться на занятие или открывать регистрацию не требуется.

В журнале фильтр «С пропусками» показывает студентов с заданным минимальным числом
пропущенных тем. Будущие занятия и занятия чужой подгруппы не учитываются;
зачёт темы с другой подгруппой сохраняется. На лекциях ожидаются все студенты
выбранного курса обучения и учебного года. У лабораторных и семинаров используется
сохранённый состав занятия; если он пуст, — явно назначенные группы или студенты
этой линии. Исходные списки и предъявления не переписываются.
Если состав неизвестен, журнал показывает «—» или минимальное известное число «≥».
Если состав курса не назначен, отображаются студенты с сохранёнными посещениями:
таблица и экспорт доступны, пропуски и оценки им не выдумываются.

Ошибочное или тестовое занятие можно удалить из расписания и журнала. Для
двухпарного курса удаляется весь блок. История хранится и доступно восстановление
с прежними ID; активную регистрацию сначала нужно завершить. При согласовании
старых занятий в плане миграции можно явно исключить тестовую строку.

Исправление последней карты доступно через **F4**; снятие связи — также от
студента (**Ctrl+U** в учебном списке). Замена владельца требует явного действия,
сохраняет предъявления и записывается в аудит. Несколько карт разрешены; при
предъявлении показывается предупреждение. Повтор не означает уход и не меняет
первое фактическое время.

## Работы, расчёт и экспорт

Раздел «Оценки» виден всегда: **Доклады**, **Контрольные работы**, **Итоги**.
Доклады включаются явным действием; контрольная добавляется с названием и исходной
шкалой. Баллы редактируются непосредственно в таблице, прямоугольник из Excel
вставляется через Ctrl+V. Двойной щелчок по студенту в докладах открывает карточку.
Настройки расчёта и веса раскрываются из итогов, сохраняя обычную таблицу простой.

Оценивание подключается по необходимости. Один доклад студента принадлежит одному
семестровому курсу и конкретному экземпляру занятия сдачи. Новая карточка получает
просматриваемое занятие, существующая сохраняет прежнюю привязку. Изменение занятия —
явное действие. Сохранение доклада не создаёт посещение.

«Найти тему…» открывает отдельный поиск рефератов по названию, разделу и номеру,
с учётом опечаток и «ё/е», как поиск студентов. Для кибербезопасности включён
справочник из 41 темы; также доступны ранее сохранённые темы своего курса.
Темы занятий в этот список не входят. Можно ввести собственное название.

Карточка содержит 18 критериев с крупными кнопками уровней вместо слайдеров.
Устное выступление и письменный реферат раскрываются отдельно; стрелки ←/→ меняют
уровень, ↑/↓ переходят к следующему критерию. Без письменного реферата 13 письменных критериев
отключены и исключены из числителя и суммы весов; пять устных работают без штрафа.
Переключение сохраняет выбранные уровни. Тема уникальна в академической группе.

У каждой письменной работы собственная исходная шкала и общий вес. Пустая ячейка
означает отсутствие результата; ноль — выставленный результат. Пока не заполнены
все обязательные работы, итог отсутствует. Непроходной выставленный балл участвует
в расчёте. Курс без оценивания не требует итоговой отметки.

Журнал, статистика и экспорт вызывают одну версионированную функцию расчёта.
Параметры меняют производные оценки, сохраняя уровни и исходные баллы. Предпросмотр
сравнивается с применённым вариантом; срез группы/специальности не меняет формулу.
Подбор ограничен границами и закреплёнными параметрами. Нормальность ограниченной
дискретной шкалы не гарантируется; диагностика после подбора не независима.

XLSX содержит одну плоскую таблицу на одном листе: идентификация, посещения тем,
доклад и занятие сдачи, наличие письменной части, исходные баллы/шкалы, итог и
полнота. Прежний CSV-обмен и приватный журнал карт доступны отдельно. Публичная
ведомость не содержит UID. CSV-текст, похожий на формулу, экранируется.

## Импорт CSV

```csv
№,ФИО,Специальность,Специализация/профилизация,Курс,Группа,№ зачётки,Средний балл всех сессий
```

Семь первых полей обязательны; восьмой столбец необязателен и игнорируется.
Поддерживаются UTF-8/BOM, Windows-1251, запятая, точка с запятой и табуляция.
Старые согласованные названия колонок и трёхколоночный CSV-обмен сохраняются.
Средний балл с десятичной точкой допустим и не участвует в оценивании.

Номер зачётки — текстовый устойчивый ключ, включая ведущие нули. Совпадающие ФИО
не объединяются. Новые специальности, профилизации, курсы обучения и группы
создаются автоматически. Пустые строки пропускаются; ошибки показывают исходный
номер строки и блокируют применение. Реальная неоднозначность группы требует
явного выбора. Объединение разных написаний названий необязательно.
Повторный импорт сохраняет ID, отсутствующих в файле студентов и историю.

## Публичное окно и клавиатура

Публичное окно открывается через «Вид → Публичное окно» отдельно от приватного.
Фон светлый, текст контрастный. Для неизвестной карты отметка сохраняется, а надпись
«Преподаватель сопоставит позже» объясняет следующий шаг без показа UID.
Первая отметка зелёная, повторная жёлтая;
ФИО исчезает по таймеру (по умолчанию 3 секунды, настройка 1–60). Публичное окно
не получает UID, исключения, пути и приватные команды. Ошибка обновления экрана
отделена от результата сохранения.

| Клавиши | Действие |
| --- | --- |
| F1 | Команды |
| F2 | Ручная отметка выбранного студента на экране занятия |
| F3 | Поиск |
| F4 | Исправить последнюю карту |
| F9 / Shift+F9 | Открыть / закрыть регистрацию |
| Ctrl+Enter | Подтвердить контекстное действие |
| Enter / Пробел в журнале | Поставить посещение в выбранных ячейках |
| F6 / Shift+F6 | Следующая / предыдущая область |
| Tab / Shift+Tab | Следующий / предыдущий элемент |
| Shift+стрелки | Выделить диапазон |
| Esc | Отложить карту / закрыть диалог / выйти из полного экрана |

Приватные команды не действуют поверх модального диалога и при фокусе публичного окна.

## Данные и миграция

Схема SQLite **4**. Версии 1–3 переходят транзакционно с согласованной копией
через SQLite Backup API, включая WAL. Старые ID, карты, предъявления, исправления,
ручные действия и история сохраняются. Новые академические соответствия не
угадываются. Старые лабораторные Java считаются двухпарными; меняется только
плановое время по утверждённому локальному плану, исходное время предъявлений
не округляется. Фиктивные повторные сканирования не создаются.

Сначала выполните репетицию, не меняющую рабочую БД:

```bash
uv run --locked attendance-lab --db /полный/путь/attendance.sqlite3 \
  --rehearse-migration /полный/путь/новый-приватный-каталог
```

Подробный порядок проверки локального плана, применения и точного отката —
[инструкция миграции](docs/MIGRATION.md). Не заменяйте БД обычным копированием
отдельного файла и не меняйте открытую БД. Приложение не останавливается принудительно.

По умолчанию реальные данные: `~/.local/share/attendance-lab/attendance.sqlite3`,
тестовые: `~/.local/share/attendance-lab/demo.sqlite3`; учитывается `XDG_DATA_HOME`.
`--db` задаёт другой путь. Одна база допускает один экземпляр приложения.
Режим real/demo проверяется также при восстановлении. GUI создаёт резервную копию
через Backup API; восстановление при закрытой регистрации сохраняет страховочную
копию. После прерывания приложение закрывает незавершённый сеанс, сохраняя отметки;
возобновление требует явного открытия регистрации.

Реальные CSV храните в `imports/`. БД, копии, планы миграции, UID, личные выгрузки,
журналы и чувствительные снимки экрана не должны попадать в GitHub. Публичный
`demo.csv` содержит только вымышленные записи.
