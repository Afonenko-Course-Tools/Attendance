# Attendance Lab 0.1.1

Локальное приложение для Linux и Python **3.14.7+**. Дисциплины и датированные занятия, учёт предъявлений PC/SC-карт, позднее сопоставление со студентами, таблица посещаемости и CSV. Три независимых окна: приватное управление, приватный журнал и публичное подтверждение.

Интернет нужен для первоначальной установки зависимостей. После установки приложение работает локально; сервер, аккаунт и облачное хранилище не используются.

## Быстрый запуск без считывателя

Распакуйте архив и перейдите в каталог `attendance-lab`. Нужен **uv 0.12.10 или новее**. Если uv ещё не установлен, используйте [официальную инструкцию](https://docs.astral.sh/uv/getting-started/installation/); установленную старую версию обновите тем же способом, которым она была установлена.

```bash
uv python install 3.14.7
uv run --locked --no-dev attendance-lab --demo
```

Режим `--demo` использует отдельную базу. Вкладка **«Устройство и окна»** содержит имитатор; выберите его в списке и нажмите **«Подключить / восстановить связь»**. В поле UID можно вводить тестовые значения, например `00 11 22 33` и `04 AB CD 12 34 56 78`. Поле видно только преподавателю.

## Запуск с ACS / PC/SC

Ваш работающий `pcsc_scan` уже подтверждает настройку ридера. Перед запуском достаточно дополнительно установить зависимости сборки Python-адаптера и, при необходимости, недостающие графические библиотеки.

Ubuntu / Debian:

```bash
sudo apt install build-essential pkg-config libpcsclite-dev swig \
  libegl1 libopengl0 libxcb-cursor0 libxkbcommon-x11-0
```

Arch Linux:

```bash
sudo pacman -S --needed base-devel pcsclite swig libglvnd \
  libxkbcommon-x11 xcb-util-cursor
```

`pyscard` 2.3.1 на Linux собирается из исходников. Заголовки PC/SC требуются даже тогда, когда `pcsc_scan` уже работает. Python, установленный через uv, содержит собственные заголовки; установка системного `python3-dev` другой версии не заменяет их.

```bash
uv run --locked --no-dev --extra pcsc attendance-lab
```

Для нового компьютера также нужны PC/SC daemon и драйвер устройства (`pcscd`, `pcsc-tools`, `libccid` в Ubuntu/Debian; `pcsclite`, `pcsc-tools`, `ccid` в Arch). Существующую рабочую настройку ридера изменять не требуется.

Во вкладке **«Устройство и окна»** обновите список, выберите нужное полное имя интерфейса и подключитесь. По вашему диагностическому выводу карты появлялись на `ACS ACR1281 1S Dual Reader 00 01`; программа не фиксирует это имя и не выбирает первый интерфейс автоматически.

При запуске без extra `pcsc` главное окно остаётся доступным, но для чтения оборудования потребуется установить extra указанной командой. Имитатор в реальном режиме отсутствует.

## Первое занятие: студенты ещё не внесены

1. В **«Дисциплины и расписание»** создайте дисциплину, затем занятие с датой, началом и окончанием. Часовой пояс предлагается по настройке Linux; при необходимости измените его в форме занятия.
2. Выберите строку занятия и нажмите **«Открыть регистрацию на выбранное занятие»**. Если текущее время вне расписания, подтвердите раннее или позднее открытие.
3. Откройте **«Публичное окно»** и **«Приватный журнал активного занятия»**.
4. В публичном окне студент увидит подтверждение только после сохранения отметки. Неизвестная карта также учитывается. UID выводится только приватно.
5. При использовании имитатора вводите тестовые UID во вкладке устройства и нажимайте **«Имитировать предъявление»**.
6. В приватном журнале на каждую карту будет одна строка. Повторное прикладывание обновляет последнее время и не отменяет присутствие.
7. Завершите регистрацию отдельной кнопкой. Программу можно закрыть: отметки сохраняются между запусками.

Просмотр другой дисциплины, занятия или отчёта **не переключает регистрацию**. Активное занятие всегда указано в верхней полосе главного окна. При переключении регистрации ранее принятые события сначала сохраняются в исходное занятие.

## CSV и позднее сопоставление

Все студенты и идентификаторы в примере CSV, тестах и демонстрационных скриншотах вымышлены.

В **«Студенты и карты» → «Импорт CSV…»** выберите файл, кодировку и разделитель; укажите колонки ID, ФИО и группы. В архиве есть [пример](examples/students.csv):

```csv
student_id;full_name;group
S001;Иванов Алексей Сергеевич;Физика-101
S002;Петрова Мария Андреевна;Физика-101
```

Проверьте предварительный просмотр до импорта. Ошибки и повторяющиеся ID блокируют применение; корректный импорт выполняется целиком. Повторный импорт обновляет студентов по ID. Совпадающие ФИО не объединяются.

Если исходный CSV не содержит ID, программа создаёт их. Сразу экспортируйте список студентов с этими ID и используйте его для повторных импортов — повторная загрузка исходного файла без ID создаст новые записи.

Выберите карту в приватном списке или журнале занятия и нажмите **«Сопоставить карту…»**. В диалоге выберите студента и проверьте число затрагиваемых занятий. Все ранее собранные отметки этой карты станут видны в его посещаемости с исходными временами.

- Одному студенту можно сопоставить несколько карт. Они дают одно присутствие на занятии.
- Уже привязанную карту нельзя незаметно назначить другому студенту.
- Для ошибочной первоначальной привязки есть отдельное действие **«Исправить ошибочную привязку…»**. Оно исправляет всю историю карты, сохраняет аудит и требует подтверждения.
- Передача той же физической карты другому владельцу с периодами владения в этой версии не поддерживается. Исправление ошибки не следует использовать для такой передачи.

## Состав и таблица посещаемости

В расписании разделены **«Ожидаемый состав»** и **«Регистрация»**. Первый столбец показывает заранее назначенных студентов, второй — уникальные прочитанные карты, распознанных студентов и карты без сопоставления. Поэтому две неизвестные карты при пустом составе отображаются как **«Карт: 2 · Студентов: 0 · Без сопоставления: 2»**, а ожидаемый состав остаётся нулевым. После сопоставления пересчитывается и история завершённых занятий. Несколько карт одного студента дают одного распознанного студента; повторные предъявления не увеличивают счётчики.

В дисциплине задайте **«Состав дисциплины…»**. Это состав по умолчанию для ещё не зафиксированных занятий. При первом открытии занятия он фиксируется и больше не меняется вслед за общим списком.

Для позднего назначения или изменения состава выделите одно или несколько занятий через Ctrl/Shift и откройте **«Состав выбранных занятий…»**. Проверьте список затрагиваемых занятий перед применением.

Во вкладке **«Посещаемость»** доступны фильтры по дисциплине, периоду, группе и студенту. После сопоставления карт таблица обновляется автоматически.

| Ячейка | Значение |
| --- | --- |
| Присутствовал + время | Есть сопоставленное предъявление |
| Нет отметки | Занятие завершено, студент ожидался, предъявления нет |
| Ожидается | Занятие ещё запланировано |
| Пока нет отметки | Регистрация открыта, студент ожидается |
| — | Студент не входит в состав и не предъявлял карту |
| Звёздочка у присутствия | Посещение вне ожидаемого состава |

Если остаются неизвестные карты, отчёт показывает уведомление о незавершённом сопоставлении. Отсутствие отметки не определяет причину пропуска; предъявление карты не измеряет продолжительность присутствия.

Экспорт:

- **Таблица CSV:** текущая матрица с учётом фильтров, без UID.
- **Присутствия CSV:** одна строка на студента и занятие, первое время с часовым поясом, без UID.
- **Приватный журнал CSV:** отдельная команда в окне журнала, включает полные UID и неизвестные карты.
- **Студенты CSV:** справочник с устойчивыми ID для последующего обновления.

Разделитель и BOM выбираются при экспорте. Для UID и ID с ведущими нулями при открытии CSV в табличном редакторе выбирайте текстовый тип колонок. Текст, похожий на формулу, экспортируется с защитным апострофом; учитывайте это при обратной загрузке таких необычных полей.

## Публичное окно

Первая успешная отметка на занятии выделяется **зелёным**, повторная — **жёлтым**. Повтор другой карты того же уже распознанного студента тоже выделяется жёлтым. На другом занятии первое предъявление вновь считается первой отметкой.

Приватные окна и диалоги всегда используют светлую тему независимо от темы рабочего стола. В приватном журнале цветная плашка и подсветка строки показывают последнее полученное подтверждение для просматриваемого занятия. Выделение строки мышью не скрывает цвет; повторное предъявление обновляет существующую строку. Подсветка — текущая обратная связь, при перезапуске она сбрасывается; сохранённые времена предъявлений остаются в журнале.

Результат и ФИО исчезают через **3 секунды**; таймер можно изменить приватно от 1 до 60 секунд. Новая карта сразу заменяет предыдущий результат. При закрытии регистрации ФИО скрывается.

Во вкладке **«Устройство и окна»** можно выбрать монитор, переместить публичное окно и включить полный экран. Esc возвращает оконный режим. Публичное окно не содержит UID, ATR, технических исключений и элементов управления студентами. Демонстрируйте аудитории только это окно.

## Данные и резервная копия

Обновление с 0.1.0: завершите приложение, распакуйте новый архив в отдельный каталог и запустите обычной командой из него. База в каталоге пользовательских данных будет использована автоматически; если раньше задавали `--db`, укажите тот же путь. Формат базы не изменён, повторный импорт студентов и карт не требуется.

По умолчанию:

- реальная база: `~/.local/share/attendance-lab/attendance.sqlite3`;
- тестовая база: `~/.local/share/attendance-lab/demo.sqlite3`.

При заданном `XDG_DATA_HOME` используется этот каталог. Точный путь виден в приватных настройках. Альтернативный путь и пояс новых занятий можно задать при запуске:

```bash
uv run --locked --no-dev --extra pcsc attendance-lab \
  --db /полный/путь/attendance.sqlite3 --timezone Europe/Minsk
```

У реальной и тестовой баз сохраняется маркер режима; открыть реальную базу через `--demo` или восстановить копию другого режима нельзя. Для одной базы допускается один экземпляр приложения.

Создавайте резервную копию через GUI: SQLite backup даёт согласованный снимок, в том числе при открытом занятии. Для восстановления сначала завершите регистрацию. Перед восстановлением автоматически создаётся страховочная копия `*.before-restore.*.sqlite3` рядом с текущей базой. Не заменяйте работающую SQLite-базу обычным копированием одного файла: рядом могут находиться её WAL/SHM-файлы.

После аварийного прерывания приложение при следующем старте завершает оставшуюся открытую регистрацию и сообщает об этом приватно. Все уже сохранённые отметки остаются; занятие можно явно открыть заново.

Рядом с базой расположен приватный технический `.log` с ротацией. Его содержимое не показывается в публичном окне и не добавляется строками в журнал карт.

Базы данных, включая демонстрационные и резервные копии, WAL/SHM-файлы, дампы, журналы, реальные списки студентов и экспорты не предназначены для GitHub. `.gitignore` исключает эти локальные данные; единственное исключение для CSV — вымышленный `examples/students.csv`. Перед коммитом проверяйте состав добавленных файлов; не обходите эти исключения через `git add -f`.

## Разработка и проверка

```bash
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pyright
QT_QPA_PLATFORM=offscreen uv run --locked pytest -q
uv build
```

Группа `dev` содержит только инструменты разработки. Для одновременной разработки с реальным считывателем добавляйте `--extra pcsc` в команды uv, которым нужны аппаратные зависимости.

Контрольный CI описан в `.github/workflows/check.yml`. Результаты проверки конкретного архива и аппаратные ограничения приведены в [VALIDATION.md](docs/VALIDATION.md). Архитектура — в [ARCHITECTURE.md](docs/ARCHITECTURE.md), исходное согласованное описание — в [requirements.md](docs/requirements.md).

Собственные исходники лицензированы MIT. PySide6/Qt и pyscard имеют собственные открытые лицензии; их бинарные зависимости устанавливаются отдельно через uv и не включены в архив проекта.
