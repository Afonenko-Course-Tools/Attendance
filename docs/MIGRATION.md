# Безопасный перенос и возврат Attendance

Текущая схема — 4. Поддерживаются исходные схемы 1, 2 и 3. Переход всех версий выполняется одной транзакцией; ошибка отменяет весь переход. До изменения создаётся согласованная копия SQLite Backup API, включающая подтверждённые записи WAL.

Новая схема сама по себе не назначает прежним занятиям семестр, курс обучения, формат, тему или группу. Эти академические решения принимает преподаватель по локальному плану. Не используйте `--migrate-only` вместо согласования исторических занятий.

## 1. Репетиция при работающем приложении

```bash
uv run --locked --no-dev attendance-lab \
  --db /полный/путь/attendance.sqlite3 \
  --rehearse-migration /полный/путь/новый-приватный-каталог
```

Рабочая база открывается только для чтения. Останавливать приложение не требуется. Каталог результата должен отсутствовать. В нём создаются:

- `original.sqlite3`: согласованная копия исходной версии;
- `candidate.sqlite3`: копия после обновления схемы;
- `plan.json`: соответствия «было → станет», количества и контрольные суммы истории;
- `review-plan.html`: автономная локальная форма согласования.

Права каталога — 700, файлов — 600. Форма не использует сеть, библиотеки CDN или внешние ресурсы. Содержимое остаётся локальным. Храните результаты в игнорируемом каталоге `backups/` вне публикуемых документов. Не отправляйте эти файлы, исходную БД, студенческие CSV, UID и чувствительные снимки экрана в GitHub или внешние сервисы.

Проверяются формат и режим `real/demo`, целостность, внешние ключи и неизменность каждого исходного столбца каждой исходной таблицы. Контрольные суммы считаются по согласованной копии. Фактическое первое и последнее время предъявления не округляются.

## 2. Решения преподавателя

Откройте `review-plan.html` обычным браузером. Для каждого семестрового курса заполните учебный год, семестр, курс обучения, формат и число пар. При необходимости добавьте курс для разделения семестров и форматов. Для каждой строки занятия выберите курс, номер темы, дату и первый слот блока.

Форма заполняет предложения: учебный год и семестр по первой дате, формат по названию дисциплины, курс обучения по однозначному прежнему составу (при его отсутствии — явно отмеченное предложение 2), темы по порядку дат и прежним названиям. Для времени предлагается ближайший допустимый первый слот по началу занятия, при равном расстоянии — более ранний. Выпадающий список показывает полное время блока, а рядом показано «было → предложено». Все эти значения — предложения для проверки, а не подтверждённые академические факты. Исходный JSON и рабочая база при этом не меняются. Одинаковый номер темы означает одну тему во всём курсе и требует одинакового названия.

Для курса с несколькими подгруппами план содержит постоянные линейки: название, день недели и первый слот. Каждая линейка получает общий состав для всех своих дат; общая программа курса задаёт темы, одинаковые во всех подгруппах. Матрица показывает сохранённые экземпляры по темам и подгруппам. Пустая клетка «Нет записи» не создаёт фиктивного занятия или посещения. Нумерацию предложений в каждой линейке нужно проверить по учебной программе.

Отработку назначайте той же подгруппе и явно отмечайте «Перенос / отработка»: её фактическая дата и слот могут отличаться от обычного расписания. Состав подгруппы объединяет только прежние зафиксированные составы выбранных источников, без вывода принадлежности из предъявлений карты. Пустой исторический состав остаётся пустым.

Старые Java-лабораторные — двухпарные. Если два прежних занятия составляют один блок, у второй строки выберите первую в выпадающем списке объединения (дата, тема и ID); обеим строкам задайте одинаковые курс, тему, дату и первый слот блока. Если у исторического двухпарного блока было только одно занятие, будет создана вторая плановая пара без новых предъявлений карты. Состав переносится по прежним ID, без выдуманных академических групп. Присутствие в любой паре засчитывает весь блок.

В колонке «Действие» тестовую строку можно пометить «Удалить тестовое занятие с восстановлением». Её учебные поля не требуются; существующий блок исключается целиком. Это обратимое скрытие: старое занятие, ID, карты, предъявления и ручные основания не удаляются. Причина и время сохраняются в аудите, восстановление записывает отдельное время. В приложении такое занятие можно вернуть из списка удалённых.

Если занятие состоялось, но ридер не работал, раздел «Добавить занятие без предъявлений» создаёт отдельное историческое занятие. Выберите семестровый курс и источник состава из старых занятий того же курса, проверьте тему, полный слот и точную дату. Предложение даты +7 дней требует отдельного подтверждения. Флажок сдвига последующих предложенных номеров включён по умолчанию: обновляются только номера и автоматически созданные названия, а пользовательские названия сохраняются. Добавления входят в `additional_lessons` утверждённого плана, не подменяя старые ID. При применении создаются завершённые занятия с фиксированным составом и **нулём предъявлений и посещений**. Посещения после проверки можно отметить отдельно обычными средствами приложения. Несогласованная дата, чужой состав, противоречивый номер темы или пересечение времени блокируют добавление.

Личные предложения преподавателя могут храниться рядом с формой в приватном `form-proposals.json`; генератор читает только допустимые поля предложений и сохраняет исходный `plan.json` неизменным. Этот файл также не должен попадать в репозиторий.

После проверки поставьте флажок утверждения и сохраните `approved-plan.json`. До этого академические данные не изменяются.

## 3. Применение плана к новой копии

Используйте исходную согласованную копию из первого шага, чтобы результат точно соответствовал утверждённому плану:

```bash
uv run --locked --no-dev attendance-lab \
  --db /полный/путь/репетиция/original.sqlite3 \
  --apply-migration-plan /полный/путь/approved-plan.json \
  --migration-output /полный/путь/новый-каталог-применения
```

Исходная копия открывается только для чтения. Результат — `candidate.sqlite3` в новом каталоге. Незаполненные решения, чужой снимок, повторяющиеся строки, несовместимое объединение и выход за сетку блокируют перенос. Применение транзакционное. Сохраняются старые ID занятий, студенты, карты, сканирования, история исправлений, ручные основания и аудит. Меняются только явно утверждённые плановые начала и окончания занятий; исходные времена хранятся в метаданных утверждённого переноса. Исходная версия остаётся в `original.sqlite3`.

Результат можно отдельно открыть новой сборкой для проверки. Перед финальной установкой закройте это окно: проверочная работа с копией не должна добавлять в неё новые рабочие события.

## 4. Финальная установка

Только после проверки результата штатно закройте рабочее приложение. Команда не останавливает процесс и не снимает его блокировку:

```bash
uv run --locked --no-dev attendance-lab \
  --db /полный/путь/attendance.sqlite3 \
  --install-migration-copy /полный/путь/применение/candidate.sqlite3
```

Команда получает ту же блокировку, что и приложение, проверяет утверждённый перенос в копии и совпадение всей исходной истории рабочей базы с моментом репетиции. Если после репетиции были новые предъявления или правки, установка отклоняется: подготовьте свежий план. Перед установкой сохраняется `*.before-rollback.<время>.sqlite3`. Сама установка выполняется SQLite Backup API, без файлового копирования поверх открытой БД.

Для отдельного обновления только структуры существует `--migrate-only`; оно также требует закрытого приложения и создаёт `*.before-migration.*.sqlite3`.

## 5. Точный возврат

Штатно закройте приложение и укажите прежнюю копию:

```bash
uv run --locked --no-dev attendance-lab \
  --db /полный/путь/attendance.sqlite3 \
  --rollback-from /полный/путь/репетиция/original.sqlite3
```

Перед возвратом создаётся ещё одна страховочная копия. Возвращается точная версия прежней схемы, без автоматического обновления. Для продолжения работы запускайте прежнюю сборку. Новая сборка при обычном запуске снова обновит схему.

Для демонстрационной базы добавляйте `--demo` во всех шагах. Смешивание режимов запрещено. Все приведённые имена и пути — примеры; реальные данные не входят в репозиторий.
