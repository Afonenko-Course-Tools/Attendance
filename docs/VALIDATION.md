Дополнительно проверены резервирование/восстановление, недопустимое смешивание баз real/demo, защита служебных SQLite-файлов, восстановление после прерывания, атомарный импорт, сохранение ID, часовые пояса и переходы летнего времени. Архитектурные тесты проверяют направление импортов между слоями и изоляцию публичного окна.

У аппаратного адаптера проверены вызовы настоящей обёртки pyscard через подменный низкоуровневый PC/SC backend: точный выбор интерфейса, T=1, APDU чтения UID, статус 9000, сохранение ведущих нулей и длинного UID, удержание карты, быстрое удаление/возврат, повторные попытки и остановка. Эти тесты проверяют программный протокол, но не заменяют подключение оборудования.

## Что требует проверки на рабочем компьютере

- Физическое чтение UID обеих представленных карт через ваш ACS ACR1281, включая постоянство UID при повторном предъявлении.
- Удаление и повторное подключение именно вашего USB-ридера и работа установленного драйвера.
- Полноэкранное публичное окно и перенос между реальными мониторами в используемой сессии Linux (Wayland/X11).
- Распознавание колонок вашего фактического CSV и выбранной кодировки.

Рекомендуемая аппаратная проверка: создайте отдельное пробное занятие, приложите каждую карту несколько раз с удалением из поля, проверьте одну строку на карту, затем сопоставьте их с тестовыми студентами и экспортируйте таблицу. Для испытания настоящего ридера используйте отдельную **реальную** базу через `--db`; режим `--demo` специально исключает аппаратуру.

## Ограничения выпуска

Один компьютер, один оператор, один явно выбранный интерфейс. Расписание состоит из конкретных занятий. Привязка карты относится к её истории целиком; смена физического владельца по периодам не реализована. Система фиксирует предъявления и не вычисляет время ухода или длительность присутствия.

При патологически зависшем нативном вызове драйвера остановка ожидания ограничена: поздние callbacks подавляются, новый запуск этого обработчика блокируется до выхода его потока. Системный драйвер Python принудительно не прерывает; при такой неисправности следует проверить устройство и перезапустить приложение.

GitHub Actions workflow включён для последующих изменений; удалённый запуск CI в рамках этой поставки не выполнялся. Wheel распространяется как Python-пакет, а не как самостоятельный исполняемый файл с встроенными Python и Qt.
